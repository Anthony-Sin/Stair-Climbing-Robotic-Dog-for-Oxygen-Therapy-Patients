# Failure-Recovery Matrix (real Go2 stack)

One row per failure mode. Columns: **Intended behavior** (what the post-fix system does),
**Telemetry signal** (the log line / topic / counter that proves it happened), and
**Test / HIL checklist** (how to verify it, on the host or hardware-in-the-loop).

This matrix reflects the behavior AFTER the 2026-07 real-stack defect fixes. It is the
first such matrix for the codebase — keep it in sync when the recovery behavior changes.

Key components:
- `low_level_control_node` — 50 Hz `/lowstate → /lowcmd` control node (the native runtime).
- `SafetyWatchdog` (`real/control/safety_watchdog.py`) — tilt / staleness / joint-limit gate.
- `command_gate` (`classify_command_age`) — follow-command freshness → FRESH / HOLD / DAMP.
- `DualPolicyRunner` / `HandoffController` — PGTT walk ↔ blind-RL climb.
- `CameraCapture` — vision-side RealSense capture (process A).
- `sport_startup_node` — the one SDK node (releases sport mode).

| Failure mode | Intended system behavior | Telemetry signal that proves it | Test / HIL checklist |
|---|---|---|---|
| **Camera loss** (RealSense USB blip / wedge) | After N consecutive frame failures, `CameraCapture._reconnect_pipeline` runs a synchronous reconnect (stop + `hardware_reset` + re-init) and broadcasts a **"degraded"** vision state on entry, **"restored"** / **"failed"** on exit, so downstream (follow controller) can HOLD instead of acting on a stale frame. Vision loop keeps returning `(None, None)` — never crashes. | Log line `[CameraCapture][VISION_STATE] degraded` then `restored`/`failed` (force-printed even when not verbose); optional registered `set_state_callback(state)`; `CameraCapture.vision_state` attribute. | Unplug/replug the D435 mid-run; confirm the VISION_STATE transitions appear and the run continues. Follow command staleness then drives HOLD downstream (see DDS/command gap row). |
| **LiDAR silence** (no PointCloud2 in lidar mode) | `lidar_heightscan_node` stops publishing `/go2/heightscan`; `low_level_control_node` falls back to a **flat height_fn** (`_make_height_fn`) — PGTT walks blind-flat rather than on a stale grid. Climb approach can still engage via the D435 depth fallback. | Absence of `/go2/heightscan`; `_make_height_fn` returns the flat lambda (no heightscan telemetry updates). | Kill the LiDAR driver in lidar mode; confirm PGTT keeps walking flat and does not act on a frozen elevation map. |
| **DDS / command gap** (vision process A dies or lags mid-run) | `classify_command_age` on a **monotonic** receipt clock: `> cmd_timeout_sec (0.4 s)` → **HOLD** (zero velocity, keep walk/climb mode, balance in place); `> cmd_damp_sec (1.0 s)` → **DAMP**, now **LATCHED** (terminal until `~/rearm`). A never-received command is HOLD (stand), never DAMP. Mid-climb, HOLD zeroes the climb forward floor too (no blind advance). | `control FAULT -> cmd_lost: damping` (error, latched); `follow command STALE -> HOLD` (warning); `finish(exit_reason="cmd_lost"/"cmd_hold")` in the run report. | `test_command_gate.py` (unit). HIL: pause the vision process; confirm HOLD within ~0.4 s and a latched DAMP within ~1 s that does NOT self-clear on command return. |
| **Vision process death mid-climb** | The climb branch honors `hold`: on a vision dropout the runner sets `cvx = 0.0` (was `max(vx, climb_vx)` — a ~0.6 s blind advance then collapse). The blind-RL policy balances in place at zero command; steering still holds the last bearing (rate-independent decay). | `DualPolicyRunner` climb telemetry `cmd_vx=0.0` while `backend=climb_blind_rl` and `hold=True`. | `test_real_dual_policy_runner.py` climb+hold case. HIL: kill vision while climbing; confirm no forward lurch. |
| **Clock / NTP step** (system time jumps forward or back) | Staleness gates (command-age + lowstate-staleness) run on `time.monotonic()`, so an NTP step cannot spuriously trip DAMP (forward jump) or blind the gate (backward jump). The publisher's wire **stamp** stays ROS-clock and is used ONLY for the transport-skew EWMA. | No spurious `lowstate_stale` / `cmd_lost` around an NTP step. Transport-skew alert `follow-command transport skew EWMA ... ms` (counted, throttled) if genuine queueing. | Step the system clock ±2 s during a run; confirm no DAMP is triggered by the step alone. |
| **Disk full** (eMMC full, flight recorder can't write) | `RealTelemetry.record_fall_diag` / `record_frame_timing` catch `IOError`/`OSError` and **count** the drop (`write_errors`) instead of propagating — the flight recorder must not kill the flight. The 50 Hz loop keeps running. | `RealTelemetry.write_errors` counter > 0; the control loop keeps publishing `/lowcmd`. | Fill the telemetry disk (or point `telemetry_dir` at a read-only path) and confirm the control node keeps running and `write_errors` increments. |
| **Sport-release failure** (MotionSwitcher can't release / SDK session dead) | `sport_startup._mode_released()` **fails closed**: on any exception it returns `False` (sport state UNKNOWN = not released), so the low-level `/lowcmd` gate never opens against a robot still driven by the sport service. After retries it publishes `release_failed` and the control node keeps waiting. | `/go2/sport_state = release_failed`; log `CheckMode failed ...; treating sport mode as NOT released (fail closed)`; the low-level node stays in its startup gate (no `/lowcmd`). | Simulate a CheckMode exception; confirm the control node does NOT start writing `/lowcmd`. |
| **Two driving stacks up** (Docker/sidecar sport stack + native low-level stack) | `low_level_control_node._interlock_guard` **refuses to start** when `GO2_SIDECAR_ACTIVE` is set (the sidecar keeps sport active; the native stack releases it — mutually exclusive by physics). Override only with `GO2_ALLOW_SPORT_ACTIVE=1` after confirming the sidecar is down. | `RuntimeError: REFUSING TO START: GO2_SIDECAR_ACTIVE is set ...` at node construction (or the loud error override log). | Set `GO2_SIDECAR_ACTIVE=1` and launch the node; confirm it aborts. See `src/real/DEPLOY.md` "Which runtime?". |
| **Tilt fault** (body tips past the mode-aware limit) | `SafetyWatchdog` tilt limit is **climb-mode aware**, single-sourced from `go2_locomotion.tilt_limits`: WALK latch-damps at `WATCHDOG_WALK_TILT_RAD` (0.52), CLIMB at `WATCHDOG_CLIMB_TILT_RAD` (1.05, above the FSM's 0.70 abort) so the handoff's **graceful abort-to-walk fires first** during a climb. A tilt latch is **terminal** until `~/rearm`, which resumes only after a posture sanity check + a **gain-ramped** stand. | `control FAULT -> tilt_exceeded: damping` (latched); `HandoffController` `handoff_disengage reason=aborted_tilt` (graceful abort) BEFORE the latch during a climb; `~/rearm accepted: posture OK -> gain-ramped resume`. | `test_real_safety_watchdog.py`; the `tilt_limits` import-time invariant asserts `FSM_ABORT < WATCHDOG_CLIMB`. HIL: tip the body during a climb; confirm the FSM aborts to walk before the watchdog latch-damps. |
| **Out-of-range joint target** | The joint-limit watchdog class is now **wired** (Go2 limits injected at construction via `go2_joint_limits()`), evaluated against THIS tick's computed targets **before** they publish (walk mode only — the blind-RL climb legitimately uses deep calf angles and has its own motor clamp). An out-of-range target latch-damps. | `control FAULT -> joint_limit: damping` (latched). | `test_real_safety_watchdog.py::test_joint_limit_trips_when_bounds_given`. |
| **Climb-handoff reachability** (does the climb feature exist this run?) | At boot the node logs which engage paths are armed: `approach_engage` (riser_dist_ahead from LiDAR `/go2/stair_detection`, else the D435 `DepthStairDetector` leading-edge fallback — reachable in flat mode) and `stall_engage` (armed once `SportModeState` body velocity arrives, else OFF). No silent unreachability. | Boot log `climb-engage paths: approach_engage=ARMED ...; stall_engage=ARMED-WHEN-VELOCITY ...`; `SportModeState subscribed on ...` or `SportModeState unavailable ...`. | Read the boot log on a hardware run; confirm at least `approach_engage=ARMED`. HIL: walk to a riser and confirm the handoff engages. |
| **Config rot** (stale weight paths) | `real_robot.yaml` weight paths are anchored to the real current files (`src/sim/models/...`), and preflight validates **the same yaml the launch loads** (`--params`), so a stale path fails preflight instead of folding the robot on a `FileNotFoundError` after sport is released. | Preflight `[FAIL] weights_present MISSING: [...]` (before any motion) instead of a control-node crash post-release. | `python -m real.verification.preflight --params src/real/config/real_robot.yaml` (must PASS with the shipped weights). |
| **Unmeasured LiDAR extrinsics** (lidar mode) | Preflight **FAILS** (not just warns) when `heightscan_mode: lidar` still carries the identity-placeholder extrinsic (a wrong extrinsic mis-registers the whole elevation map). Flat mode: warn only (extrinsic unused). | Preflight `[FAIL] lidar_extrinsics PLACEHOLDER ... [FAIL: heightscan_mode=lidar]`. | `check_lidar_extrinsics("lidar")` returns not-ok; edit `pointcloud_interface._EXTRINSICS` with the measured transform, re-run preflight. |
